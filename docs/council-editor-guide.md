# Council editor guide

Sign into https://app.pagescms.org/ using your own authorized GitHub account. Select the council repository and branch. Saving on main will publish when Cloudflare is connected, so review your text first.

- **Site settings:** home headline, introduction, approved photo and image description, school/social links and optional contact/volunteer information.
- **Project Play:** campaign story, status and approved donation link. Enter confirmed CAD goal and raised amount, then enable progress. Leave unknown amounts empty; zero raised is valid. Amounts above the goal remain visible while the bar stops at 100%.
- **Initiatives:** add a title, description and link. Switch Visible on to publish. Lower display order comes first; Featured initiatives appear before other visible initiatives. Hidden examples are not real announced programs.
- **Milestones:** add approved steps, optional confirmed dates and status. Lower display order comes first. Undated milestones can be published without inventing a date.
- **Fundraising actions:** add approved external URLs and use Active to publish. The website does not collect payments.
- **Updates and announcements:** switch Published on; newest publication dates appear first.
- **Events:** supply a confirmed start, location and registration link. Dates are displayed in Toronto time.
- **FAQs and quick links:** use Visible and display order. Quick links appear in the footer.
- **Images:** use only approved assets, avoid student photographs without permission, and describe meaningful images in the image description field. Upload modestly sized web images (ideally under 500 KB).

After saving, wait for the deployment and check the live page on your phone. If you do not see a change, ask the administrator to inspect Cloudflare deployment status. Use GitHub history to restore accidental edits; ask the administrator before deleting content. Do not publish unconfirmed totals, deadlines, endorsements or payment links.
